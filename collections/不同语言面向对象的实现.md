# 不同语言面向对象的实现

面向对象可以从两个层次理解：**写代码时，如何把数据与行为组织在一起；执行代码时，如何找到并调用正确的方法。** 各语言的差别既体现在 `class` 等语法上，也体现在对象布局、属性查找、方法分派和生命周期上。

> 下文的结构图都是示意图。语言规定的行为与某个编译器、虚拟机的实现细节需要区分，不能把一种常见布局当成所有实现的保证。

## 1. 先统一概念与例子

| 概念 | 要解决的问题 | 卡牌例子 |
| --- | --- | --- |
| 对象 | 如何表示有自身状态的实体？ | 一张基础分为 10 的卡牌 |
| 类或类型 | 如何描述一类对象的结构与能力？ | `Card` 描述普通卡牌 |
| 封装 | 如何让状态通过受控入口被使用和修改？ | 通过 `score()` 读取分数，计算细节留在对象内部 |
| 继承 | 如何建立类型关系并复用已有实现？ | `MultiplierCard` 继承 `Card` |
| 组合 | 如何通过持有其他对象来复用能力？ | 倍率卡持有基础卡牌数据 |
| 多态 | 同一调用如何适用于不同实现？ | 普通卡与倍率卡都能调用 `score()` |

封装不只是“把字段与方法放在一起”，还涉及模块边界、访问限制和不变量。继承是组织类型和复用代码的一种手段；实现多态也可以使用接口、trait、鸭子类型等机制。

贯穿全文的需求：

- 普通卡：`score = base`。
- 倍率卡：`score = base × multiplier`。
- 统一的计分入口依次调用卡牌的计分方法，不需要逐个判断具体类型。

各语言的主示例都应输出：

```text
10
30
```

读例子时，重点追踪三个问题：**数据放在哪里？方法放在哪里？调用时怎么选中实现？**

## 2. Lua：table、元表与 `__index`

Lua 没有内建的 `class` 关键字，但提供了 table、函数、闭包和元表，可以据此构建对象模型。不能简单概括为“Lua 的面向对象就是 mix-in”。官方《Programming in Lua》也展示了使用 table 与元表模拟类的方式。[参考：Lua 对象编程](https://www.lua.org/pil/16.html)、[模拟类](https://www.lua.org/pil/16.1.html)。

### 2.1 完整例子

以下代码使用 Lua 5.1 即可运行：

```lua
local Card = {}
Card.__index = Card

function Card:new(base)
    local obj = { base = base }
    return setmetatable(obj, self)
end

function Card:score()
    return self.base
end

local MultiplierCard = {}
MultiplierCard.__index = MultiplierCard
setmetatable(MultiplierCard, { __index = Card })

function MultiplierCard:new(base, multiplier)
    local obj = Card.new(self, base)
    obj.multiplier = multiplier
    return obj
end

function MultiplierCard:score()
    return Card.score(self) * self.multiplier
end

local function print_score(card)
    print(card:score())
end

print_score(Card:new(10))
print_score(MultiplierCard:new(10, 3))
```

### 2.2 `:` 是接收者参数的语法糖

```lua
function Card:score()
    return self.base
end

-- 等价的定义：
Card.score = function(self)
    return self.base
end

-- 对简单变量 card 而言，下面两种调用等价：
card:score()
card.score(card)
```

方法本质上是接收对象参数的函数。冒号调用自动传入接收者；一般表达式作为接收者时，冒号形式还保证该表达式只求值一次。

### 2.3 查找路径比“类语法”更重要

对于倍率卡实例 `obj`：

```text
obj 自己的字段：base、multiplier
    │ 找不到 score
    ▼
obj 的元表：MultiplierCard
    │ __index = MultiplierCard
    ▼
在 MultiplierCard 中找 score → 找到倍率版本

如果某个字段在 MultiplierCard 中也不存在：
    ▼
MultiplierCard 自己的元表中的 __index = Card
    ▼
继续在 Card 中查找
```

`__index` 是读取缺失字段时的后备机制，不是把父类字段复制进实例。它也可以是函数，从而自定义查找规则。字段已经存在时通常不会触发它；值为 `false` 仍表示字段存在，`nil` 才表示缺失。[参考：Lua 5.1 元表规则](https://www.lua.org/manual/5.1/manual.html#2.8)。

这里有两个容易混淆的设置：

```lua
MultiplierCard.__index = MultiplierCard
-- 控制以 MultiplierCard 为元表的实例，缺失字段去哪里找。

setmetatable(MultiplierCard, { __index = Card })
-- 控制 MultiplierCard 这个 table 自身，缺失字段去哪里找。
```

### 2.4 mix-in 是另一种复用方式

mix-in 可以理解为给类型混入一组能力，例如把“可描述”的函数复制到卡牌类型中：

```lua
local Describable = {}

function Describable:describe()
    return "base=" .. self.base
end

-- 接在主示例后运行。
for name, method in pairs(Describable) do
    assert(Card[name] == nil, "method conflict: " .. name)
    Card[name] = method
end

print(Card:new(10):describe()) -- base=10
```

这段代码采用复制式混入：复制后，替换 `Describable.describe` 不会自动替换 `Card.describe`。通过 `__index` 委托则是在后续查找时继续访问被委托的表，两者的更新传播方式不同。

阅读 Lua 类库时，可以依次检查：构造函数创建了什么 table、实例的元表是谁、`__index` 指向哪里、`extend` 如何连接父子类型、`implement` 是否在复制方法。`extend`、`implement`、`new` 等名字通常是类库约定，不是 Lua 关键字。

## 3. JavaScript：原型链，以及构建在其上的 `class`

### 3.1 完整例子

```javascript
class Card {
  constructor(base) {
    this.base = base;
  }

  score() {
    return this.base;
  }
}

class MultiplierCard extends Card {
  constructor(base, multiplier) {
    super(base);
    this.multiplier = multiplier;
  }

  score() {
    return super.score() * this.multiplier;
  }
}

function printScore(card) {
  console.log(card.score());
}

printScore(new Card(10));
printScore(new MultiplierCard(10, 3));
```

### 3.2 实例属性与原型方法分开存放

上例的 `base`、`multiplier` 是实例自己的属性，普通实例方法定义在对应的 `prototype` 对象上：

```text
倍率卡实例
    → MultiplierCard.prototype
    → Card.prototype
    → Object.prototype
    → null
```

对于这里的普通属性，`card.score` 先查实例，再沿原型链查找，直到命中或到达 `null`。[参考：ECMAScript 普通对象的属性读取](https://tc39.es/ecma262/multipage/ordinary-and-exotic-objects-behaviours.html#sec-ordinaryget)。

不使用 `class`，也能手工建立类似的委托关系：

```javascript
const cardMethods = {
  score() { return this.base; }
};
const card = Object.create(cardMethods);
card.base = 10;
console.log(card.score()); // 10
```

`class` 为常见的构造和继承模式提供语法，但也有严格模式、私有字段等独立规则，不能把所有 class 特性都当成普通属性赋值的简单替换。

### 3.3 找到方法不等于绑定接收者

```javascript
const card = new Card(10);
const f = card.score;

// f();                    // this 为 undefined，读取 base 会报错
console.log(f.call(card));  // 10
console.log(f.bind(card)()); // 10
```

普通方法的 `this` 通常由调用方式决定。把函数取出来保存，不会自动保留原接收者。原型链负责找到函数，调用形式负责确定 `this`，这两步需要分开理解。

## 4. Python：类对象、属性查找与描述符

### 4.1 完整例子

```python
class Card:
    def __init__(self, base):
        self.base = base

    def score(self):
        return self.base


class MultiplierCard(Card):
    def __init__(self, base, multiplier):
        super().__init__(base)
        self.multiplier = multiplier

    def score(self):
        return super().score() * self.multiplier


def print_score(card):
    print(card.score())


print_score(Card(10))
print_score(MultiplierCard(10, 3))
```

### 4.2 为什么取出方法后还能调用？

```python
card = Card(10)
f = card.score
print(f())                       # 10
print(f.__self__ is card)         # True
print(f.__func__ is Card.score)   # True
```

通过实例访问类中定义的普通函数时，描述符机制会产生绑定方法，保留接收者 `card`。调用 `f()` 时，这个对象作为 `self` 传入。[参考：Python 描述符与方法绑定](https://docs.python.org/3/howto/descriptor.html#functions-and-methods)。

### 4.3 属性查找不是简单的“实例 → 类”

在没有自定义 `__getattribute__` 等行为的常规情况下，可把实例属性读取概括为：

1. 沿类的 MRO 寻找同名类属性；如果命中的是数据描述符，优先使用它。
2. 否则检查实例自己的属性字典（如果有）。
3. 再使用先前沿 MRO 找到的非数据描述符或普通类属性。
4. 若仍失败，且类型提供了 `__getattr__`，再由它处理。

普通函数是非数据描述符，`property` 是数据描述符。MRO 是方法解析顺序，多继承时尤其重要。`super()` 按 MRO 继续查找，不应理解为无条件调用“源码中直接写出的父类”。[参考：Python 属性查找机制](https://docs.python.org/3/howto/descriptor.html#invocation-from-an-instance)。

这个例子也体现了鸭子类型：`print_score` 没有要求参数必须继承 `Card`，只要对象提供能正确调用的 `score()` 就可以。命名约定 `_base` 不等于编译器强制的私有访问控制。

## 5. Java：类继承、接口与动态分派

### 5.1 完整例子

保存为 `Main.java`，先执行 `javac Main.java`，再执行 `java Main`。

```java
interface Scorable {
    int score();
}

class Card implements Scorable {
    private final int base;

    Card(int base) {
        this.base = base;
    }

    @Override
    public int score() {
        return base;
    }
}

class MultiplierCard extends Card {
    private final int multiplier;

    MultiplierCard(int base, int multiplier) {
        super(base);
        this.multiplier = multiplier;
    }

    @Override
    public int score() {
        return super.score() * multiplier;
    }
}

public class Main {
    static void printScore(Scorable card) {
        System.out.println(card.score());
    }

    public static void main(String[] args) {
        printScore(new Card(10));
        printScore(new MultiplierCard(10, 3));
    }
}
```

### 5.2 声明类型与实际类型各起什么作用？

```java
Scorable card = new MultiplierCard(10, 3);
System.out.println(card.score()); // 30
```

编译器根据声明类型 `Scorable` 检查是否有 `score()`；执行时根据实际对象找到重写实现。Java 类只能直接继承一个类，但可以实现多个接口。

普通可重写实例方法具有动态分派语义；`static` 方法、字段访问和方法重载不应套用这条规则。重载主要在编译期根据参数等信息选择签名，重写则涉及运行期实现选择。[参考：Java 方法调用规则](https://docs.oracle.com/javase/specs/jls/se25/html/jls-15.html#jls-15.12)。

JVM 可以借助类型元数据、方法表、内联缓存等机制实现调用，JIT 也可能把某次调用内联。**动态分派描述的是语言行为，不代表机器码每次都必须查一次表。** 不应把某个 JVM 的对象头或表布局当成 Java 语言规范。

## 6. C++：值语义、`virtual` 与常见虚表实现

### 6.1 完整例子

```cpp
#include <iostream>

class Card {
private:
    int base_;

public:
    explicit Card(int base) : base_(base) {}
    virtual ~Card() = default;

    virtual int score() const {
        return base_;
    }
};

class MultiplierCard : public Card {
private:
    int multiplier_;

public:
    MultiplierCard(int base, int multiplier)
        : Card(base), multiplier_(multiplier) {}

    int score() const override {
        return Card::score() * multiplier_;
    }
};

void print_score(const Card& card) {
    std::cout << card.score() << '\n';
}

int main() {
    Card normal(10);
    MultiplierCard boosted(10, 3);
    print_score(normal);
    print_score(boosted);
}
```

### 6.2 虚调用常见的实现形态

```text
对象                         与类型相关的虚表
┌──────────────────┐         ┌─────────────────────────┐
│ 隐含的虚表指针   │ ──────→ │ score 对应的函数入口    │
│ 基类与派生类数据 │         │ 其他虚函数相关信息      │
└──────────────────┘         └─────────────────────────┘
```

编译器常用虚表指针和虚表实现 `virtual`；多继承等情况会更复杂，不能保证一个对象始终只有一个虚表指针。虚表布局由 ABI 等实现规则约束，C++ 语言本身不要求必须使用这一具体结构。[参考：Itanium C++ ABI 虚表布局](https://itanium-cxx-abi.github.io/cxx-abi/abi.html#vtable)。

与 Java 不同，C++ 普通成员函数默认不是虚函数。需要通过基类引用或指针获得重写行为时，应在基类声明 `virtual`。派生类写 `override` 可以让编译器检查是否确实重写了虚函数。

### 6.3 对象切片与生命周期

```cpp
MultiplierCard boosted(10, 3);
Card copy = boosted;        // 只复制 Card 基类部分，发生切片
std::cout << copy.score();  // 10
```

引用或指针可以保留对完整派生对象的访问，按值复制成基类对象则会丢失派生部分。上例的 `print_score` 因而使用 `const Card&`。

示例对象具有自动存储期，在离开作用域时析构。C++ 还可结合 RAII 和智能指针管理资源。基类若要支持通过基类指针删除派生对象，通常应提供虚析构函数；上例已经这样处理。

## 7. C#：类与接口，以及显式的 `virtual` / `override`

### 7.1 完整例子

```csharp
using System;

interface IScorable
{
    int Score();
}

class Card : IScorable
{
    private readonly int baseScore;

    public Card(int baseScore)
    {
        this.baseScore = baseScore;
    }

    public virtual int Score() => baseScore;
}

class MultiplierCard : Card
{
    private readonly int multiplier;

    public MultiplierCard(int baseScore, int multiplier) : base(baseScore)
    {
        this.multiplier = multiplier;
    }

    public override int Score() => base.Score() * multiplier;
}

class Program
{
    static void PrintScore(IScorable card)
    {
        Console.WriteLine(card.Score());
    }

    static void Main()
    {
        PrintScore(new Card(10));
        PrintScore(new MultiplierCard(10, 3));
    }
}
```

### 7.2 C# 与 Java 最容易混淆的地方

C# 普通类实例方法默认不可重写，需要基类声明 `virtual` 或 `abstract`，派生类使用 `override`。`new` 声明的同名方法是隐藏成员，通过基类类型访问时不会得到同样的虚方法重写行为。[参考：C# 多态](https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/object-oriented/polymorphism)。

C# 类具有引用语义；也有 `struct` 值类型，可以实现接口，但不支持像类那样继承另一个用户定义的结构体。不能把 C# 的全部对象模型都等同于 Java 的类模型。

运行时通常由 CLR 的类型信息支持虚调用和接口调用，并可能经 JIT 优化。垃圾回收负责回收托管对象的内存；文件等资源仍应通过 `IDisposable`、`using` 等机制及时释放。

## 8. Go：结构体、方法与隐式接口实现

### 8.1 完整例子

```go
package main

import "fmt"

type Scorable interface {
    Score() int
}

type Card struct {
    base int
}

func (c Card) Score() int {
    return c.base
}

type MultiplierCard struct {
    card       Card
    multiplier int
}

func (c MultiplierCard) Score() int {
    return c.card.Score() * c.multiplier
}

func printScore(card Scorable) {
    fmt.Println(card.Score())
}

func main() {
    printScore(Card{base: 10})
    printScore(MultiplierCard{card: Card{base: 10}, multiplier: 3})
}
```

### 8.2 复用实现用组合，统一调用用接口

`MultiplierCard` 持有一个 `Card`，不是 `Card` 的子类。只要方法集合满足 `Scorable`，就实现了该接口，无需写 `implements`。[参考：Go 接口](https://go.dev/doc/effective_go#interfaces)。

也可以使用匿名嵌入 `struct { Card }` 提升字段和方法，让某些访问更简洁，但嵌入不会建立传统的基类与派生类关系，也不会自动产生虚方法重写机制。

Go 的接口值在语义上包含动态类型和动态值，可据此选择实现。具体运行时布局属于实现细节；不必把接口理解成一个单纯的对象地址。

### 8.3 值接收者与指针接收者影响方法集合

```go
type Counter struct{ n int }

func (c *Counter) Inc() { c.n++ }

type Incrementer interface{ Inc() }

var _ Incrementer = &Counter{} // 成立：*Counter 的方法集合包含 Inc
// var _ Incrementer = Counter{} // 不成立：Counter 的方法集合不含 Inc
```

某些直接方法调用可以由编译器自动取地址，但这不会改变接口实现检查所依据的方法集合。[参考：Go 方法集合规范](https://go.dev/ref/spec#Method_sets)。

Go 的可见性以包为边界，由标识符首字母是否大写决定。上例的小写字段不向其他包导出，但同一包内仍可访问。

## 9. Rust：`struct + impl + trait`，区分静态与动态分派

### 9.1 完整例子

```rust
trait Scorable {
    fn score(&self) -> i32;
}

struct Card {
    base: i32,
}

impl Scorable for Card {
    fn score(&self) -> i32 {
        self.base
    }
}

struct MultiplierCard {
    card: Card,
    multiplier: i32,
}

impl Scorable for MultiplierCard {
    fn score(&self) -> i32 {
        self.card.score() * self.multiplier
    }
}

// 泛型：通常通过单态化实现静态分派。
fn score_static<T: Scorable>(card: &T) -> i32 {
    card.score()
}

// trait 对象：动态分派。
fn print_score(card: &dyn Scorable) {
    println!("{}", card.score());
}

fn main() {
    let normal = Card { base: 10 };
    let boosted = MultiplierCard {
        card: Card { base: 10 },
        multiplier: 3,
    };

    assert_eq!(score_static(&normal), 10);
    assert_eq!(score_static(&boosted), 30);
    print_score(&normal);
    print_score(&boosted);
}
```

### 9.2 trait 不意味着一定要查虚表

`score_static<T: Scorable>` 的调用方提供具体类型，编译器通常通过单态化为类型生成相应代码，并可能内联。

`&dyn Scorable` 隐去了具体类型，运行时通过 trait 对象关联的方法表选择实现。可将其理解为“数据指针 + 虚表指针”的示意结构。`dyn` 的使用还要求 trait 满足动态兼容性条件，并非所有 trait 都能直接用作 trait 对象。[参考：Rust trait 对象与分派](https://doc.rust-lang.org/book/ch18-02-trait-objects.html)。

Rust 没有传统的类实现继承，可以通过组合持有数据，通过 trait 描述共同能力。trait 的默认方法能复用行为，supertrait 能表达能力依赖，但都不等于继承父类的实例字段。

对象的有效期与资源释放由所有权、借用和 `Drop` 等机制管理，不依赖追踪式垃圾回收。上例的 `&self` 表示共享借用当前值，不会转移它的所有权。

## 10. C：用结构体与函数指针手工搭建分派机制

C 没有类与虚方法语法，但能用结构体保存状态，用函数指针表示可替换行为。下面采用“一个状态结构 + 可替换计分函数”的最小设计，避免引入手工继承所需的类型转换。

```c
#include <stdio.h>

typedef struct Card Card;
typedef int (*ScoreFn)(const Card *self);

struct Card {
    int base;
    int multiplier;
    ScoreFn score;
};

int normal_score(const Card *self) {
    return self->base;
}

int multiplier_score(const Card *self) {
    return self->base * self->multiplier;
}

void print_score(const Card *card) {
    printf("%d\n", card->score(card));
}

int main(void) {
    Card normal = {10, 1, normal_score};
    Card boosted = {10, 3, multiplier_score};
    print_score(&normal);
    print_score(&boosted);
    return 0;
}
```

这个例子没有建立继承关系，却实现了统一入口下的行为替换。当前每个实例直接保存一个函数指针；如果方法很多，可以让实例保存一个“函数指针表”的地址，在多个对象间共享这张表。

这有助于理解虚表的思路：方法调用不一定是直接跳转到固定函数，也可以先通过数据结构选择函数。C++ 的真实 ABI 还涉及析构、类型信息、多继承等规则，比这个最小模型复杂。

## 11. 横向比较：相同的调用，不同的实现路径

| 语言 | 状态与行为如何组织 | 常见复用方式 | 本文中如何选择计分实现 | 接收者 |
| --- | --- | --- | --- | --- |
| Lua | 实例 table 与保存方法的 table | `__index` 委托、组合、mix-in | 缺失字段触发元表查找 | `:` 自动传 `self` |
| JavaScript | 对象属性与 prototype 上的方法 | 原型链、组合 | 属性沿原型链查找后调用 | 普通方法由调用形式确定 `this` |
| Python | 实例、类对象与描述符 | 类继承、组合 | 属性查找、MRO、方法绑定 | 显式声明 `self`，绑定方法自动传入 |
| Java | 类字段与实例方法 | 单类继承、多接口、组合 | 可重写实例方法动态分派 | 隐式 `this` |
| C++ | 类对象与成员函数 | 多继承、组合、模板 | `virtual` 支持动态分派 | 隐式 `this` |
| C# | 类、结构体与成员 | 单类继承、多接口、组合 | 虚方法或接口调用选择实现 | 隐式 `this` |
| Go | struct 与关联方法 | 组合、嵌入、接口 | 接口调用依据动态类型 | 显式声明接收者 |
| Rust | struct、impl 与 trait | 组合、trait 默认方法 | 泛型静态分派或 `dyn` 动态分派 | `self`、`&self`、`&mut self` 等 |
| C | struct 与普通函数或函数指针 | 组合、手工函数表 | 调用保存的函数指针 | 手工传入指针 |

这张表只总结本文示例。多种语言同时支持其他形式的多态，例如 C++ 模板、Java/C# 泛型、Lua/JavaScript/Python 的动态协议。

### 11.1 判断“继承还是组合”的一个具体例子

如果游戏后续出现“倍率卡、发光倍率卡、可冻结的发光倍率卡”，把每种组合都建成子类，会产生大量类型。可以把卡牌视为核心数据，再持有倍率、外观、状态效果等组件：

```text
Card
├── 基础数据：base = 10
├── 计分效果：Multiplier(3)
├── 外观效果：Glow
└── 状态效果：Frozen
```

继承适合表达稳定且能被正确替换的类型关系；组合适合能力独立变化、运行期可配置的场景。选择应依据模型是否清晰，而不是语言有没有 `class`。

### 11.2 对象里必须存着所有方法吗？

同类对象通常共享方法实现，实例主要保存自身状态和必要的类型或查找信息。Lua/JavaScript 常通过委托对象共享函数，Python 常把函数放在类上，C++ 常把代码与实例数据分开。

不过，“方法共享”也不是绝对规则：闭包、实例上的函数属性、JavaScript 箭头函数字段，都可以产生每实例各自持有的函数。

## 12. 附：设计模式与单例模式

设计模式描述常见设计问题的解决结构；对象模型描述语言如何表示对象、查找成员和执行调用。单例模式可以借助这些机制实现，但它本身不是面向对象的实现机制。

例如，Lua 模块返回一个 table，可以让调用方共享状态：

```lua
-- score_service.lua
local service = { total = 0 }

function service:add(value)
    self.total = self.total + value
end

return service
```

```lua
-- main.lua：将 score_service.lua 放在模块搜索路径中。
local a = require("score_service")
local b = require("score_service")

a:add(10)
print(b.total) -- 10
print(a == b)  -- true
```

在同一个 Lua 状态中，使用同一模块名、正常保留 `package.loaded` 缓存时，重复 `require` 会返回缓存的模块值。清空缓存、使用不同模块名或切换独立 Lua 状态，都可能改变结果；这不是跨进程的“全局唯一”。[参考：Lua 5.1 的 require](https://www.lua.org/manual/5.1/manual.html#pdf-require)。

共享可变状态会让测试和依赖关系变得隐蔽。仅为了方便访问数据时，也可以把服务对象作为参数传入。
